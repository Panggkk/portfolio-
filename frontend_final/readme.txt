1. สิ่งที่ทำใน backend
คือใช้โค้ดเดียวกับที่ส่งกลางภาค คัดลอกมาแล้วเอามาใส่ในโฟลเดอร์ ิbackend ใน frontend_final
ไฟนอลไม่ได้ไปแก้ตรงนี้เลย

1.1 มีออกแบบฐานข้อมูล มีตารางดังนี้
Region -> เก็บพวกจังหวัด/ภูมิภาค + ประชากร
Constituencies -> เขตเลือกตั้ง (เชื่อมกับ Regions)
Parties-> พรรคการเมือง
Candidates-> ผู้สมัคร ส.ส. เขต (เชื่อมพรรค + เขต)
Voters-> ผู้มีสิทธิเลือกตั้ง (มีสถานะโหวต 2 แบบคือแบบพรรคการเมือง(บัญชีรายชื่อ) กับแบบส.ส.เขต)
Ballots-> บันทึกการโหวตแบบไม่ระบุตัวตน 

มี enum
VoteType แบบ PartyList(บัญชีรายชื่อ)กับ Constituency(เขต)

1.2 โดยมีกำหนดเงื่อนไข ข้อมูลที่รับในแต่ละตารางดังนี้

ตาราง Voters->เลขบัตรประชาชนต้องเป็นตัวเลข ต้องมี 13 หลัก ห้ามลงทะเบียนซ้ำ ต้องอยู่ในเขตที่มีจริง
ตาราง Candidate ->ชื่อห้ามซ้ำ หมายเลขแคนดิเดตห้ามซ้ำในเขตเดียยวกัน พรรคมีจริง เขตมีจริง
ตาราง Region/Constituency/Party->ตรวจไอดีซ้ำไหม ตรวจชื่อซ้ำ ตรวจค่าต้อง valid (เช่น population > 0)

ตาราง Ballot 
-> ถ้าเป็น Constituency vote ต้องมี candidate_id ห้ามมี party_id
-> ถ้าเป็น PartyList vote ต้องมี party_id ห้ามมี candidate_id

1.4 API ที่ทำมา
=>ส่วนของ Region & Constituency
POST /regions/ คือ เพิ่มจังหวัด
GET /regions/ คือ ดูจังหวัด
POST /constituencies/ คือ เพิ่มเขต
GET /constituencies/ คือ join แสดงชื่อจังหวัด + เขต

=>z ของ Party & Candidate
POST /parties/ คือ เพิ่มพรรค
GET /parties/ คือ ค้น/กรองพรรค
POST /candidates/ คือ เพิ่มผู้สมัคร
GET /candidates/ คือ join 3 ตาราง (candidate + party + constituency)

=>ของ Voter
POST /voters/ คือ ลงทะเบียนผู้มีสิทธิเลือกตั้ง
GET /voters/ คือ ดูรายชื่อ + เขต + สถานะโหวต
มี field:
has_voted_const คือโหวต ส.ส.เขต
has_voted_list คือโหวต พรรคการเมืองหรือ ส.ส.แบบบัญชีรายชื่อ 

=>ของการ vote
POST /vote/cast
- ตรวจ voter มีอยู่จริง
- เช็คสิทธิการโหวตซ้ำ
- แยกตาม vote_type
- ตรวจห้ามโหวตข้ามเขต
- อัปเดตสถานะ voter
- บันทึกลง Ballots แบบ anonymous

=>ของการ turnout ตารางผลเลือกตั้ง
GET /results/turnout
- มีใช้ GROUP BY
- แยกเป็นเขต กับแยกประเภทโหวต(เขต / party list)

=>แสดงผลเลือกตั้ง
GET /results/stats
- แสดงคะแนนผู้สมัครรายเขต
- แสดงคะแนนพรรค
- ใช้ JOIN + GROUP BY + ORDER BY คะแนนมากไปน้อย

2. สิ่งที่ทำใน frontend
- เพิ่มไฟล์ api.js ในไฟล์ lib ไว้เชื่อม backend รวมทั้งหมดที่เชื่อมกับbackend (GET / POST ทั้งหมด เช่น พรรค ผู้สมัคร ผู้มีสิทธิ คะแนน)
- ทำ landing page หรือหน้าหลัก เชื่อมไปยังหน้าต่างๆที่ทำตามโจทย์ไว้แล้ว
- ทำตามโจทย์ โจทย์ละ 1 หน้า คือเพิ่มไฟล์ในโฟลเดอร์หน้าเพิ่มอีก 4หน้า(4 โฟลเดอร์ ไม่รวมหน้าหลักหรือ landing page) 
มีหน้า ข้อมูลพรรคการเมือง/หน้าผู้มีสิทธิเลือกตั้ง/หน้าบันทึกคะแนน/หน้ารายงานผลการเลือกตั้ง
แต่ละโฟลเดอร์มีไฟล์ +page.svelte(UI) กับไฟล์ +page.server.js(load กับ actions) ในทุกโฟลเดอร์ 
- ทำตรง +layout.svelte ใส่หน้า ทำ navbar

=> หน้าบันทึกลงคะแนนเสียง :ทำตามโจทย์บันทึกการลงคะแนนรายบุคคลแบบไม่ระบุตัวตน / แสดงจํานวนผู้ลงคะแนนแยกตามเขตเลือกตั้งทั้งแบบพรรค 
และ ส.ส.เขต ได้ มีการลงคะแนนโหวต ตรวจสิทธิ์ กันโหวตซ้ำ
- ลงคะแนนแบบรายบุคคล (ไม่เก็บตัวตนผลโหวต)
- แยกประเภท:ส.ส.เขต or บัญชีรายชื่อ
- ตรวจสอบสิทธิผู้โหวต
- กันการโหวตซ้ำ (has_voted_const / list)
- filter ผู้สมัครตามเขตที่อยู่
- บันทึกคะแนนผ่าน API /vote/cast

=> หน้าผู้มีสิทธิเลือกตั้ง : เพิ่ม / แสดง รายชื่อผู้มีสิทธิ์เลือกตั้ง โดยมีรายละเอียดของเขตเลือกตั้ง พร้อมทั้งสามารถ อัพเดท สถานะการ
ลงคะแนนได้
- เพิ่มรายชื่อผู้มีสิทธิ
- แสดงรายชื่อทั้งหมด
- แสดงเขตเลือกตั้ง
- แสดงสถานะ:ลงคะแนนแล้ว / ยังไม่ได้ลงคะแนนแล้ง
- มีjoin ข้อมูลเขต (region_name)
- จากค่าconst_id ไปใช้const_number

=> หน้าข้อมูลพรรคการเมือง (รวมถึงผู้สมัคร ส.ส.เขต) : เพิ่ม / แสดง รายชื่อพรรคการเมือง ผู้สมัคร ส.ส. เขต โดยมีรายละเอียดของเขตเลือกตั้งประกอบ
- เพิ่มพรรคการเมือง
- เพิ่มผู้สมัคร ส.ส.เขต
- แสดงข้อมูลทั้งหมด
- party_id ต้อง > 0
- candidate_number ต้อง > 0
- ห้ามพรรคส่งผู้สมัครซ้ำในเขตเดียวกัน ก็คือ 1พรรค1เขต


=> หน้ารายงานผลการเลือกตั้ง :เพิ่ม / แสดง รายชื่อพรรคการเมือง ผู้สมัคร ส.ส. เขต โดยมีรายละเอียดของเขตเลือกตั้งประกอบ
- แสดงผลคะแนน:ส.ส.เขต (ตามrank) /พรรคการเมือง
- filter ตามเขตเลือกตั้ง
- join ข้อมูลชื่อพรรค + ผู้สมัคร

3.อธิบายการทำงาน

1)การเตรียมข้อมูลก่อนใช้งาน

ระบบจะต้องมีข้อมูลพื้นฐานครบก่อน มีที่หลงเหลือจากมิดเทอมมาบ้าง เช่น เขตเลือกตั้ง พรรค และผู้สมัคร
* ถ้าไม่มีข้อมูล → จะไม่สามารถแสดงตัวเลือกให้ใช้งานได้
* dropdown / list จะดึงจากข้อมูลจริงเท่านั้น

ถ้าข้อมูลไม่พร้อม → UI จะไม่ให้เลือกหรือไม่แสดงปุ่ม action บางส่วน

2)การลงทะเบียนผู้มีสิทธิ
>>ก่อนกด “บันทึกผู้มีสิทธิ”
* ต้องกรอกเลขบัตรประชาชนครบ 13 หลัก
* ต้องไม่ซ้ำกับคนเดิม
* ต้องเลือกเขตให้ถูกต้อง

>>ถ้าข้อมูลไม่ครบ:
* ปุ่ม submit จะถูก disable หรือกดแล้วไม่ส่งค่า
* ระบบจะไม่เรียก API ลงทะเบียน

3) การโหวต

>>ก่อนกดปุ่ม “โหวต” : ระบบจะเช็คเงื่อนไขทั้งหมดแบบ real-time:
>>มี เงื่อนไขสำคัญ
* ต้องมี voter_id จริง
* ต้องยังไม่เคยโหวตในประเภทนั้น

  * has_voted_const = false (สำหรับเขต)
  * has_voted_list = false (สำหรับพรรค)
* ต้องเลือกผู้สมัครหรือพรรคก่อน
* ถ้าเป็น ส.ส.เขต → ต้องอยู่เขตเดียวกับผู้สมัคร
* ต้องเลือก vote type ให้ครบ (เขต / พรรค)

->ถ้าไม่ผ่าน
* ปุ่มโหวตจะ disabled หรือกดไม่ได้
* หรือถ้ากด จะไม่เรียก API `/vote/cast`
* ไม่มีการบันทึกคะแนนเกิดขึ้น


4)การบันทึกคะแนน 

เมื่อกดโหวตผ่านเงื่อนไขแล้ว ระบบจะทำ:
1. ตรวจสิทธิอีกครั้งฝั่งระบบ (กันโกง)
2. ส่งข้อมูลไปบันทึกคะแนน
3. อัปเดตสถานะ voter ทันที
โหวตแล้ว → เปลี่ยน has_voted = true
4. บันทึกลง Ballots แบบไม่ระบุตัวตน
ถ้าข้อมูลไม่ครบตอน submit → API จะ reject ทันที


5) การแสดงรายชื่อผู้สมัคร / พรรค

ระบบจะ filter อัตโนมัติก่อนแสดงผล
* เลือกเขต → แสดงผู้สมัครเฉพาะเขตนั้น
* เลือกประเภท → แสดงเฉพาะพรรคหรือ candidate

 ถ้า filter ไม่ครบ → รายการจะว่าง และปุ่มเลือกจะไม่ทำงาน


6) หน้าผู้มีสิทธิเลือกตั้ง

การจัดการข้อมูล voter มี logic แบบนี้:
* ถ้าไม่มี const_id → ไม่สามารถบันทึก
* ถ้าเลือกเขตไม่ถูก → ไม่อัปเดตสถานะ
* ปุ่ม update สถานะจะกดได้เฉพาะ record ที่ valid

ดูตอนอัพเดต ให้กดลงบันทึกคะแนนที่หน้าบันทึกลงคะแนน

7) หน้าข้อมูลพรรค / ผู้สมัคร
ระบบควบคุมก่อนเพิ่มข้อมูล:
* party_id ต้องมีค่า > 0
* candidate_number ต้องไม่ซ้ำในเขต
* ต้องเลือกเขตและพรรคก่อนกดเพิ่ม
ถ้าไม่ครบ → ปุ่มเพิ่มจะ disabled หรือไม่ submit

8) หน้ารายงานผล
* ถ้าไม่มีข้อมูลโหวต → แสดง “ไม่มีข้อมูล”
* filter เขต → ถ้าไม่เลือกเขต จะไม่ query ผลลัพธ์
* ranking จะคำนวณเฉพาะข้อมูลที่ valid

ตรงอัพเดตข้อมูลสถานะการโหวต เนื่องจากใน backend ที่มีตอนนั้นไม่ได้ทำ API PUT แก้ตรงสถานะ voter โดยตรงแบบอัปเดตค่าโดยตรง
ก็เลยใช้้วิธีอัปเดตสถานะโหวต คนกดโหวตแล้วส่งไปที่ POST /vote/cast แทน 
โดย backend จะอัปเดตค่า has_voted(บัญชีรายชื่อ กับ เขต) ให้เองหลังบันทึกคะแนน โหวตเสร็จสถานะเปลี่ยน
ส่วน frontend จะทำหน้าที่ re-fetch ข้อมูลใหม่แล้วอัปเดต UI เพื่อแสดงสถานะโหวตล่าสุด เปลี่ยนจากยังไม่ได้โหวตเป็นโหวตแล้ว
